ノートフィットAI
データ駆動で身体を変える。AI搭載型フィットネス・栄養管理プラットフォーム

📖 概要
「Notefit_AI」は、フィジーク大会への出場経験という原体験から生まれた、トレーニングと栄養の一元管理アプリです。 既存の記録アプリは「記録すること」がゴールになりがちですが、本アプリは「記録から次のアクションを決めること」に焦点を当てています。 トレーニング強度やPFCバランス（タンパク質・脂質・炭水化物）のログをAIが解析し、知識がない初心者でもトップレベルの管理ができるようサポートします。

🎯ターゲット
コンテスト参加者：フィジークやボディビルなど、極限の調整が求められる層
アスリート: パフォーマンス向上のために厳密な栄養管理が必要な層
健康志向の一般ユーザー: 「何を食べて、どう動いても気づかない」という課題を持つ層
🧑‍💻 チーム体制・役割
メンバー：2名（エンジニア2名）

役割: プロジェクトリーダー / バックエンドエンジニア

バックエンド設計: Firebase (Firestore) の NoSQL データ設計。読み取りコストと削減整合性を考慮した正規化・非正規化の判断。
API実装: Pythonを用いたデータ解析ロジックの実装。
プロジェクト管理: 開発スケジュールの策定、Git フローの運用ルールの策定。
🛠 使用技術
フロントエンド: React Native (Expo)
バックエンド: Firebase (認証、Firestore、Cloud Functions)
AI・分析：Python（データ解析・レコメンドロジック）
ツール: GitHub、Notion (タスク管理)
💡こだわりポイント（技術的挑戦）
①ユーザーの行動に基づくパーソナルAIの実装
匿名チャットボットではなく、ユーザーの実データ（過去のトレーニング体重、体重経過、摂取カロリー）をコンテキストとしてAIに渡すことで、個人に特化したアドバイスを生成します。

例：「シアトルよりベンチプレスの重量が落ちています。炭水化物の摂取量が不足している可能性があるため、トレーニング前に〇〇を摂取することを推奨します」のような具体的な提案機能。
② スケーラビリティを意識したデータ設計
ようなユーザー増加と、AIによる大量のデータ読み込みを想定し、将来のFirestoreのデータ構造を最適化しました。

システムアーキテクチャ
sequenceDiagram 参加者 User を 👤 User 参加者 App を 📱 App (React Native) 参加者 Auth を 🔐 Firebase Auth 参加者 DB を 🔥 Firestore 参加者 CF を ⚙️ Cloud Functions (Python) として

Note over User, App: 【フェーズ1：起動時】
User->>App: アプリ起動
App->>Auth: ログイン状態確認 (onAuthStateChanged)
Auth-->>App: ✅ 認証OK (User Token)

Note over User, App: 【フェーズ2：記録 & AI分析】
User->>App: トレーニング記録入力

%% ここが重要：書き込み時にトークンが裏で検証される
App->>DB: データ保存 (with Token)
Note right of DB: 🛡️ Security Rulesで<br>本人確認と権限チェック

%% ここからバックエンド処理
DB->>CF: トリガー発火 (onCreate/onUpdate)
CF->>CF: 🐍 PythonでAI分析実行
CF->>DB: アドバイス書き込み
DB-->>App: リアルタイム更新
App-->>User: アドバイス表示
